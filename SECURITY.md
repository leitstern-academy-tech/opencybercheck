# Security Policy

## Supported versions

OpenCyberCheck is currently in an early development phase and has not yet published a production-ready release. Security updates will initially be applied to the latest version of the `main` branch.

## Reporting a vulnerability

Please do not report suspected security vulnerabilities through public GitHub issues, discussions, or pull requests.

Report them privately by email to:

**[info@lsacademytech.com](mailto:info@lsacademytech.com)**

Please include, where possible:

* A description of the suspected vulnerability.
* The affected component or file.
* Steps required to reproduce the issue.
* The potential security impact.
* Any suggested mitigation or remediation.
* A safe method of contacting you for follow-up questions.

Do not include real credentials, personal data, customer information, or confidential infrastructure details in your report.

## Response and disclosure

We will review submitted reports and aim to acknowledge them within seven calendar days. Confirmed vulnerabilities will be investigated and addressed according to their severity and impact.

Please allow reasonable time for investigation and remediation before publicly disclosing a suspected vulnerability. We will coordinate disclosure with the reporter whenever practical.

## Scope

This policy covers the source code, security rules, schemas, sample files, and documentation maintained in this repository. Vulnerabilities in unrelated third-party services or dependencies should also be reported to their respective maintainers when appropriate.
