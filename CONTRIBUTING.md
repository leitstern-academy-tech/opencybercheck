# Contributing to OpenCyberCheck

Thank you for your interest in contributing to OpenCyberCheck. Contributions, suggestions, and constructive feedback are welcome.

## Ways to contribute

You can support the project by:

* Proposing relevant SME cybersecurity use cases.
* Suggesting transparent and verifiable security rules.
* Reviewing documentation and technical designs.
* Testing sample assessment profiles.
* Reporting reproducible bugs and documentation problems.
* Improving remediation guidance and security control mappings.
* Providing non-sensitive sample data for testing.
* Contributing source code and automated tests.

## Before making a contribution

Before starting a substantial change, please open an issue describing:

* The problem or use case.
* The proposed solution.
* The components that may be affected.
* Any relevant security or privacy considerations.

This allows the proposed approach to be discussed before significant development work begins.

## Pull requests

Pull requests should:

* Address one focused change.
* Include a clear title and description.
* Reference the relevant issue where applicable.
* Include or update tests when functionality changes.
* Update documentation when behaviour or interfaces change.
* Avoid unrelated formatting or structural changes.

## Security and sensitive information

Never submit credentials, personal data, customer information, private keys, access tokens, or sensitive infrastructure details.

Do not report suspected security vulnerabilities through public issues or pull requests. Follow the private reporting process described in [SECURITY.md](SECURITY.md).
